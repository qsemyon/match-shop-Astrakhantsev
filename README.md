# Практика EF Core: интернет-магазин спичек «Чирк»

## Письмо от заказчика

> «Здравствуйте! Меня зовут Аркадий Серников, у меня маленький интернет-магазин спичек «Чирк». Пока я всё записываю в тетрадку, и она уже не справляется. Нужна база данных: кто у нас покупает, что мы продаём и кто что заказал. Задачи буду присылать по одной, делайте по порядку.»

За пару вы делаете консольное приложение на C# и EF Core с базой PostgreSQL из трёх таблиц:

| Таблица | Что хранит |
| --- | --- |
| Покупатели | имя, телефон, город |
| Товары | спички: название, цена, сколько спичек в коробке, остаток на складе |
| Заказы | кто заказал, какой товар, сколько коробок |

Каждый шаг устроен одинаково:

- **Пример** — готовый код с пояснениями. Его можно переносить в проект как есть.
- **Задание** — то же самое, но со своими данными.
- **Усложнение** — похожая задача посложнее, в ней нужно подумать.

Правила:

- Весь код в одном проекте. `Program.cs` растёт шаг за шагом, старый код не удаляйте.
- При каждом запуске база создаётся заново, поэтому программа всегда проходит все шаги с начала.
- Если в задании есть вопрос, отвечайте комментарием в коде рядом с решением.

## Шаг 0. Подготовка

Все работают в GitHub Codespaces.

1. Откройте шаблон проекта: [ZubkovApa/EF-core](https://github.com/ZubkovApa/EF-core).
2. Нажмите **Use this template → Create a new repository**. Название — `match-shop-фамилия` латиницей, видимость — **Public**.
3. В своём новом репозитории нажмите **Code → Codespaces → Create codespace on main**. Первый запуск занимает несколько минут: поднимаются .NET и PostgreSQL.
4. В терминале выполните `dotnet run`. Должна появиться строка `Магазин спичек «Чирк»: проект запущен!`

Что лежит в проекте:

| Файл | Для чего |
| --- | --- |
| `Program.cs` | основной код: всё, что делает программа |
| `Models.cs` | классы таблиц |
| `ShopContext.cs` | контекст базы: подключение и список таблиц |

## Шаг 1. Покупатели и товары

> «Начнём с простого: мне нужен список покупателей и список товаров.»

### Пример

Таблица покупателей. В `Models.cs`:

```csharp
public class Customer
{
    public int Id { get; set; }              // первичный ключ: EF узнаёт его по имени Id
    public string Name { get; set; } = "";   // имя
    public string Phone { get; set; } = "";  // телефон
    public string City { get; set; } = "";   // город
}
```

В `ShopContext.cs`:

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Logging;

public class ShopContext : DbContext
{
    public DbSet<Customer> Customers { get; set; }   // таблица Customers

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseNpgsql("Host=localhost;Database=match_shop;Username=postgres;Password=postgres");
        options.LogTo(Console.WriteLine, LogLevel.Information);   // показывать SQL, который отправляет EF
    }
}
```

В `Program.cs`, после строки с приветствием:

```csharp
using var db = new ShopContext();
db.Database.EnsureDeleted();   // удалить базу, если она осталась с прошлого запуска
db.Database.EnsureCreated();   // создать базу и таблицы по классам
```

Запустите `dotnet run` и найдите в выводе `CREATE TABLE "Customers"`. Если SQL мешает читать вывод программы, строку с `LogTo` можно временно закомментировать.

### Задание

Создайте таблицу товаров. Для каждого вида спичек заказчик хочет знать:

- название;
- цену коробка в рублях;
- сколько спичек в коробке;
- сколько коробок осталось на складе.

Создайте класс `Product`, добавьте `DbSet<Product> Products` в контекст, запустите и найдите `CREATE TABLE "Products"`. Для денег в C# используют тип `decimal`.

### Усложнение

> «У некоторых спичек есть описание, например „горят даже под дождём“. А у некоторых его нет.»

Добавьте товару описание, которое может отсутствовать. Сравните в `CREATE TABLE "Products"` столбец с названием и столбец с описанием. Чем они отличаются и почему?

## Шаг 2. Заказы

> «Теперь главное: кто что заказал. В одном заказе один товар и количество коробок.»

### Пример

Заказ, связанный с покупателем. В `Models.cs`:

```csharp
public class Order
{
    public int Id { get; set; }
    public int Quantity { get; set; }                 // сколько коробок

    public int CustomerId { get; set; }               // внешний ключ: Id покупателя
    public Customer Customer { get; set; } = null!;   // сам покупатель
}
```

`null!` говорит компилятору: значение появится позже, его заполнит EF.

В класс `Customer` добавьте список его заказов:

```csharp
public List<Order> Orders { get; set; } = new();
```

В `ShopContext` добавьте таблицу:

```csharp
public DbSet<Order> Orders { get; set; }
```

Запустите и найдите в `CREATE TABLE "Orders"` строку с `FOREIGN KEY ("CustomerId") REFERENCES "Customers"`.

### Задание

Заказ пока не знает, какой товар купили. Свяжите `Order` с `Product` так же, как с `Customer`: внешний ключ, свойство с товаром и список заказов в классе `Product`. Проверьте, что в `CREATE TABLE "Orders"` теперь два `FOREIGN KEY`.

### Усложнение

> «Хочу видеть, когда сделан заказ.»

Добавьте заказу дату и время. Какой тип C# вы выбрали и какой тип столбца получился в PostgreSQL?

## Шаг 3. Заполнение

> «Вот первые покупатели и товары из тетрадки. Заносите в базу.»

### Пример

Два покупателя. В `Program.cs`, после `EnsureCreated`:

```csharp
Console.WriteLine("=== Шаг 3 ===");

var ivan = new Customer { Name = "Иван Петров", Phone = "+7 900 111-22-33", City = "Омск" };
var olga = new Customer { Name = "Ольга Смирнова", Phone = "+7 900 444-55-66", City = "Томск" };
db.Customers.Add(ivan);
db.Customers.Add(olga);
db.SaveChanges();   // только здесь данные уходят в базу
```

Найдите в выводе `INSERT INTO "Customers"`.

### Задание

- Добавьте ещё трёх покупателей со своими данными.
- Добавьте не меньше пяти видов спичек: свои названия, цены и остатки. Цены сделайте разными, хотя бы два товара дешевле 100 ₽.

### Усложнение

> «Вот заказы за прошлую неделю.»

Добавьте не меньше четырёх заказов. Один покупатель должен сделать два заказа, а у одного покупателя заказов быть не должно. Как сказать заказу, кто покупатель и какой товар? Подсказка: в заказ можно передать не Id, а сам объект.

Если в шаге 2 вы добавили дату и получили ошибку про `Kind=Local`, прочитайте её внимательно. Чем `DateTime.Now` отличается от `DateTime.UtcNow`?

## Шаг 4. Выборка

> «Покупатели спрашивают, что у нас подешевле. Нужны списки.»

### Пример

Покупатели из Омска по алфавиту:

```csharp
Console.WriteLine("=== Шаг 4 ===");

var omsk = db.Customers
    .Where(c => c.City == "Омск")   // только из Омска
    .OrderBy(c => c.Name)            // по алфавиту
    .ToList();                       // здесь запрос уходит в базу

foreach (var c in omsk)
    Console.WriteLine($"{c.Name}, {c.Phone}");
```

Найдите в выводе SQL с `WHERE` и `ORDER BY`.

### Задание

Выведите:

1. Спички дешевле 100 ₽ от дешёвых к дорогим: название и цену.
2. Сколько видов спичек есть на складе, то есть остаток больше нуля. Подсказка: `Count`.
3. Три самых дорогих товара. Подсказка: `OrderByDescending` и `Take`.

### Усложнение

> «Хочу видеть все заказы и сколько мы заработали.»

Выведите каждый заказ одной строкой:

```text
Иван Петров — Каминные — 3 шт. — 450 ₽
```

Сумма заказа — цена товара, умноженная на количество. В конце выведите общую выручку по всем заказам. Подсказка: имя покупателя и название товара подтягиваются через `Include`.

## Шаг 5. Изменение

> «Иван сменил номер телефона. А ещё поставщик поднял цены.»

### Пример

Новый телефон покупателя:

```csharp
Console.WriteLine("=== Шаг 5 ===");

var customer = db.Customers.First(c => c.Name == "Иван Петров");   // найти
customer.Phone = "+7 900 999-00-00";                                  // изменить
db.SaveChanges();   // EF сам видит, что изменилось, и отправляет UPDATE
```

Найдите в выводе `UPDATE "Customers"`.

### Задание

1. Сделайте все спички дороже на 10%. Одного `SaveChanges` в конце достаточно. Подсказка: у дробных чисел типа `decimal` в конце пишут букву m: `1.1m`.
2. Один из товаров закончился: поставьте ему остаток 0.

### Усложнение

> «Мне нужна функция „Оформить заказ“.»

Напишите код, который оформляет заказ по покупателю, товару и количеству коробок:

- если на складе хватает — создайте заказ и уменьшите остаток товара;
- если не хватает — выведите «Недостаточно на складе» и ничего не меняйте.

Проверьте оба случая. Почему заказ и новый остаток важно сохранить одним `SaveChanges`?

## Шаг 6. Удаление

> «Ольга попросила удалить её из базы. И уберите из каталога всё, чего нет на складе.»

### Пример

Удаление покупателя:

```csharp
Console.WriteLine("=== Шаг 6 ===");

var leaving = db.Customers.First(c => c.Name == "Ольга Смирнова");   // найти
db.Customers.Remove(leaving);                                         // пометить на удаление
db.SaveChanges();                                                     // отправить DELETE
```

Найдите в выводе `DELETE FROM "Customers"`.

### Задание

Удалите все товары, которых нет на складе, то есть с остатком 0. Подсказка: `RemoveRange`. После удаления выведите, сколько товаров осталось.

### Усложнение

> «Один покупатель обиделся и просит удалить его. Но у него были заказы.»

Удалите покупателя, у которого есть заказы. Найдите в выводе все `DELETE`: что стало с его заказами? Почему так произошло и хорошо ли это для магазина?

## Сдача

1. После каждого шага делайте коммит с названием шага, например `Шаг 3. Заполнение`: вкладка **Source Control** слева → сообщение → **Commit** → **Sync Changes**.
2. Перед отправкой проверьте, что `dotnet run` проходит все шаги без ошибок.
3. В конце пришлите ссылку на свой репозиторий. Он должен быть публичным.
